The sequence

When a new hole shows up

  1. 01

    A person reads it

    We decide whether it affects your store. Tools help us watch. A person makes the call.

  2. 02

    We try the fix on a copy

    A private copy, not the shop your customers use. If it breaks, only the copy is affected.

  3. 03

    We place a test order

    We update the live store

A fix can break checkout. Skipping it can leave a door open.

CyberWall is the careful step in the middle, for an owner who has a shop to run rather than a security team. People do the watching, the decisions, and the writing. Monitoring tools and standard checks help. This is not a claim that no automation is used, and it is not a claim that a store cannot be broken into.

What you can expect

  • Someone follows security news for the software your store uses.
  • Fixes are tried on a private copy first.
  • Checkout is tested after the change.
  • A rollback is prepared before the live update.
  • You get a plain-English note, not a raw log.

What we will not claim

  • That your store cannot be hacked. No one can promise that.
  • That a plugin update fixes every problem. Some fixes, including PHP itself, have to be done by the host.
  • That we replace backups, good passwords, or your hosting company.
  • That we are a large firm. This is early access, and we would rather say so.

A real week, October 2026

PHP2Shell, and what it means for a shop

PHP is the software underneath many stores, including WooCommerce, WordPress, Magento, and Shopware. In October 2026 two serious holes were found in PHP itself. Their public IDs are CVE-2026-109618 and CVE-2026-109619. A CVE is the public number given to a known security hole. Each is scored 9.2 on the CVSS scale, which rates them critical.

Patched
21 October 2026. CISA's alert that day names the fixed releases PHP 8.5.12, 8.4.27, 8.3.36, and 8.2.35.
Wide reach
The bugs go back to PHP 5.4, so a store can be affected even when its own code and plugins are fine.
Not a plugin fix
Updating plugins does not fix this. The PHP version on the server has to change, and that is often something only the host can do.

Attack attempts were reported before the fix was public. Researchers have reproduced the bugs in test environments. Sansec also says an attack needs specific knowledge of the server and specific conditions on it, so this is not automatic for every shop, and it is not a reason to panic. It is a reason to have someone check what it means for yours.

CISA's advice, if a server cannot be updated quickly or is still on PHP 8.1 or older, is to take that PHP system offline until it is patched or upgraded. That decision sits with you and your host. We can help you prepare what to ask them.

This is the kind of week CyberWall is for: notice it, work out whether your store is affected, test on a private copy, check checkout, and help get the right PHP version onto the live server, with a short note about what happened.

Sources: Sansec Forensics Team, “PHP2Shell: PHP RCE (CVE-2026-109618, CVE-2026-109619)”, 21 October 2026. CISA, “Critical Vulnerabilities in PHP Require Immediate Patching”, 21 October 2026.

Questions

Do I need to be technical?

No. We do the technical work and explain it in plain English. If we need something from you, we say what it is and how to do it.

Do you guarantee my store will not be hacked?

No. Nobody honestly can. We reduce risk by fixing known holes quickly and carefully, with a test copy, a checkout check, and a rollback prepared. We do not replace backups, passwords, or your host.

What if an update would break the store?

That is why the fix is tried on a private copy first. If it causes trouble there, it does not go onto the live store. A person tells you, and we look for a safer way. If something unexpected happens after a live update, the rollback is there.

Does early access commit me to a plan?

No. It is a request for a conversation. We are opening early access to a small number of stores so each one can be looked after properly. This website does not take payment.
